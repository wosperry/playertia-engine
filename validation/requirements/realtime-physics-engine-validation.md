## 0. 文档控制

### 0.1 文档目的

本文档定义实时物理仿真表盘引擎在 PC 环境中的测试目标、测试原则、测试架构、输入模型、
验证判据、测试场景、覆盖要求、性能预算和验收标准。

本文档的最终目标不是证明动画“看起来像真的”，而是证明：

1. 引擎实现了指定的数学模型；
2. 坐标、力矩、动量、能量和状态转换符合模型约束；
3. 固定步长求解在声明的参数包络内数值稳定并向参考解收敛；
4. 极端、随机和异常输入不会造成非法状态、未定义行为或不可恢复发散；
5. 测试体系能够发现符号错误、重复重力、重复冲量、错误积分顺序等典型物理缺陷；
6. 算法复杂度、热状态大小和更新时间为未来 MCU 实时运行保留足够预算；
7. 测试框架可复用于发条、陀螺、指尖陀螺、摇号等后续物理模型。

### 0.2 适用范围

本文档覆盖：

- 世界坐标系、表盘坐标系和 IMU 坐标系之间的数学转换；
- 重力向量和表心有效场；
- 移动、旋转表盘中的非惯性参考系模型；
- 单根刚性指针的质量属性、力矩、约化动量和角运动；
- 重力、平移惯性、旋转基座、阻尼、时间目标、触摸和可选弹性力矩；
- 固定步长、半隐式 Euler、子步和输入区间预积分；
- 物理状态机、控制权仲裁和连续性交接；
- 可选二段柔性指针的数学验证接口；
- 确定性、鲁棒性、性能、内存、长期运行和可扩展性验证。

### 0.3 明确不在本文档范围内

本文档暂不涉及：

- 测试程序或测试工具代码开发；
- ESP32-S3 固件移植与实机驱动；
- IMU、触摸屏、RTC、显示屏等硬件驱动实现；
- UI、渲染风格、帧动画和视觉验收；
- 菜单、应用切换、产品功能和商业需求；
- 姿态融合算法本身的产品调参和传感器标定流程；
- 表盘美术、音效、功耗、电池和整机功能。

姿态融合结果、传感器级数据契约与物理引擎的接口会被验证，但硬件采集质量和驱动正确性
不属于本阶段验收。

### 0.4 规范性用语

本文档使用以下含义：

- **必须**：发布验收的强制要求；
- **不得**：明确禁止；
- **应**：原则上必须满足，只有经记录的工程理由才可偏离；
- **可**：允许但不强制；
- **硬失败**：出现一次即判定对应测试门失败；
- **参考解**：解析解或与产品实现相互独立、经收敛证明的高精度数值解；
- **标称包络**：预期日常运行的参数和输入范围；
- **支持包络**：引擎承诺保持合法、稳定并执行安全策略的最大范围；
- **故障域**：超出物理或数据契约的非法输入范围。

### 0.5 验证结论边界

PC 测试可以证明数学实现、数值稳定性、复杂度趋势和可移植性准备情况。PC 耗时不得直接
换算成 ESP32-S3 最坏执行时间。未来 MCU 时限必须在真实 ESP32-S3、最终编译选项和最终
任务竞争环境中再次验收。

## 1. 被测试对象定义

### 1.1 被测试对象

被测试对象为：

> 实时物理仿真引擎（Physics Simulation Engine）。

其职责是根据带时间语义的基座运动、物理参数和交互输入，推进一个或多个物理对象的
权威状态。对当前表盘，物理对象主要为三根相互独立的指针。

引擎正确性以内部物理状态和数学残差为准，不以渲染图像、指针贴图位置或主观手感为准。

### 1.2 输入

测试系统必须能够向被测引擎提供下列输入：

| 输入类别 | 主要字段 | 单位或约定 |
|---|---|---|
| 世界状态真值 | 表心位置、速度、加速度，表壳姿态 | 测试夹具与参考判据使用，不要求直接注入 SUT |
| 设备姿态 | `q_WB` 或 `R_WB` | `B → W` |
| 重力 | `g^W=(0,0,-g0)`、`g^B` | `g0=9.80665 m/s²` |
| 表心有效场 | `a_eff,O^B` | `m/s²`，定义为 `g^B-A_O^B` |
| 基座角运动 | `Ω^B`、必要时 `α^B` | `rad/s`、`rad/s²` |
| 区间量 | `J_eff`、`M_Ω` | 有效场冲量、角速度外积积分 |
| 传感器级输入 | 加速度计比力、陀螺仪、时间戳、数据质量状态 | IMU 或表盘坐标系 |
| 外部物理输入 | 力、作用点、广义力矩、冲量 | 必须声明坐标系和作用对象 |
| 触摸输入 | 捕获、目标角、目标角速度、释放、数据质量状态 | 未包裹角优先 |
| 时间输入 | 各针 `TIME_REF` 目标角和目标角速度 | 连续目标，只读 |
| 离散命令 | 进入物理、开始回归、异常恢复、模式切换 | 明确事件时刻 |
| 参数输入 | 质量、质心、一阶矩、惯量、阻尼、刚度、限值 | SI 单位 |

若输入是三维外力，必须同时给出作用点，验证器据此计算：

\[
\tau_{\mathrm{external}}
=
\left[\mathbf r_{\mathrm{application}}
\times
\mathbf F_{\mathrm{external}}\right]_z
\]

其中 `r_application` 是从该指针转轴到作用点的矢量，并与 `F_external` 在同一坐标系、
同一时刻表达。

不得把未声明作用点的任意三维“力”直接解释为指针广义力矩。

每个测试用例必须声明注入层。世界状态真值始终属于测试夹具；`INJ-A` 用例向 SUT 注入
由真值派生的数学核心量，`INJ-B` 用例向 SUT 注入传感器级时间线。除专门的一致性故障
测试外，不得把 `q/g/a_eff` 与原始 IMU 当作多套相互独立的真值同时驱动物理状态。

### 1.3 输出

被测引擎和测试适配层至少应向记录器暴露：

| 输出类别 | 要求 |
|---|---|
| 权威状态 | 每根指针未包裹角 `θ`、约化动量 `p`，柔性模式下的全部广义坐标和动量 |
| 派生状态 | 相对角速度 `θ̇=p/I-Ω_z`、角加速度或离散速度增量 |
| 几何状态 | 指针轴向、切向、质心和针尖在表盘系中的位置 |
| 可选世界状态 | 由世界真值和表盘状态派生的质心世界位置，仅供测试判据使用 |
| 力矩账本 | 各分项力矩、总力矩、各区间广义冲量 |
| 能量账本 | 动能、势能、外部做功、控制做功、触摸做功、累计耗散 |
| 状态机 | 全局状态、单针状态、控制权、转换原因 |
| 安全状态 | 限速、限能、饱和、非法输入、降级、恢复、overrun 标志 |
| 时间状态 | 基础步、子步、消费的输入区间、输入序号 |
| 性能状态 | 单次更新时间、峰值工作区和分配计数 |

引擎不必维护无法由六轴 IMU 长期观测的绝对世界位置。需要验证世界位置时，由输入模拟器
保存的世界真值与引擎相对状态共同派生，不得要求被测引擎双积分加速度来伪造绝对位置。

每个可能随模式改变权威性的字段必须带有明确的 authority/valid 语义。在物理模式，
`p` 是权威速度状态；动画模式必须二选一：

1. 每个动画快照同步 `p=I(θ̇+Ω_z)`，保持该字段有效；
2. 将 `p` 标记为 dormant/invalid，并在返回物理模式的交接边界重新同步。

不得在动画期间输出一个看似有效但与 `θ̇` 不一致的 `p`。

“未包裹角”是逻辑状态契约，不代表必须用单个 `float32` 无限累加。为避免大圈数后丢失
相位精度，MCU 等价路径必须采用已声明的精度保持方案，例如 `int64` 圈计数加有界相位，
或等价的周期重基准。记录器应能无歧义重建逻辑未包裹角。

### 1.4 被测对象分层

为了隔离错误，测试必须按以下层次建立：

| 层级 | 验证对象 | 典型错误 |
|---|---|---|
| `L0` | 参数、单位和数据契约 | 非法惯量、坐标系未声明、时间区间重叠 |
| `L1` | 数学基础与坐标转换 | 四元数方向相反、轴交换、叉积符号错误 |
| `L2` | 有效场、力矩和能量 | 重力重复、质量因子错误、阻尼做正功 |
| `L3` | 单针动力学与积分器 | 积分顺序错误、动量双权威、步长不收敛 |
| `L4` | 状态机与控制交接 | TIME_REF 覆盖角度、释放清零动量 |
| `L5` | 多速率完整数据通路 | 只取最新样本、冲量重复、采样相位敏感 |
| `L6` | 极端、随机、长期和性能 | NaN、内存增长、截止期错失、隐性发散 |

姿态融合器不是本说明书的主要被测对象。物理核心必须能直接接收已知真值 `q_WB`；
`q_WB→g^B`、传感器数据契约和有效场恢复属于本说明书范围。若未来把
Madgwick、Mahony 或 EKF 合入同一软件库，融合器应另建精度、收敛、偏置和可观测性测试，
其误差不得与物理求解器误差共用一条容差。

### 1.5 核心正确性问题

测试必须回答以下问题：

1. 当前状态是否满足上游文档规定的方程？
2. 同一个物理量是否始终在同一个坐标系、单位和时间点表达？
3. 传感器比力是否被正确解释为合成有效场，而没有重复加入重力？
4. 基座平移和旋转是否通过约束与惯性项影响指针，而不是通过经验动画直接改角度？
5. 每根指针是否根据自己的质量分布、惯量和阻尼独立响应？
6. 时间、触摸和安全模块是否只通过声明的力矩、冲量或明确动画通道作用？
7. 数值求解是否在固定步长策略下稳定、连续并向同一连续模型收敛？
8. 物理引擎是否可以确定性重放并定位首次数学分歧？

## 2. 数学验证基线

### 2.1 坐标系与姿态约定

测试系统固定使用以下右手坐标系：

- 世界坐标系 `W`：`+z_W` 竖直向上；
- 表盘坐标系 `B`：原点为表心，`+x_B` 向屏幕右，`+y_B` 向屏幕下，
  `+z_B` 指向屏幕内部；
- IMU 坐标系 `M`：芯片原始轴系，通过固定旋转 `C_BM` 转换到 `B`。

旋转约定为：

\[
\mathbf v^W=R_{WB}\mathbf v^B,\qquad
\mathbf v^B=R_{BW}\mathbf v^W,\qquad
R_{BW}=R_{WB}^{T}
\]

`q_WB` 与 `R_WB` 含义一致，四元数采用 Hamilton 乘法、标量在前。必须验证：

\[
[0,\mathbf v^W]
=
q_{WB}\otimes[0,\mathbf v^B]\otimes q_{WB}^{*}
\]

\[
[0,\mathbf v^B]
=
q_{WB}^{*}\otimes[0,\mathbf v^W]\otimes q_{WB}
\]

### 2.2 重力与表心有效场

世界重力为：

\[
\mathbf g^W=(0,0,-g_0),\qquad g_0=9.80665\ \mathrm{m/s^2}
\]

表盘系重力为：

\[
\mathbf g^B=R_{BW}\mathbf g^W
\]

表心世界加速度为 `A_O^W` 时：

\[
\mathbf a_{\mathrm{eff},O}^{B}
=
R_{BW}(\mathbf g^W-\mathbf A_O^W)
=
\mathbf g^B-\mathbf A_O^B
\]

表心比力满足：

\[
\mathbf f_O^B=\mathbf A_O^B-\mathbf g^B
\]

因此生产动力学的低成本输入为：

\[
\boxed{
\mathbf a_{\mathrm{eff},O}^{B}=-\mathbf f_O^B
}
\]

如果 IMU 位于相对表心的固定偏心位置 `r_OS^B`：

\[
\boxed{
\mathbf a_{\mathrm{eff},O}^{B}
=
-\mathbf f_S^B
+\boldsymbol\alpha^B\times\mathbf r_{OS}^B
+\boldsymbol\Omega^B\times
  (\boldsymbol\Omega^B\times\mathbf r_{OS}^B)
}
\]

验证系统必须专门检测以下禁用实现：

\[
\tau(\mathbf g^B)+\tau(-\mathbf f_O^B)
\]

因为 `-f_O^B` 已经包含重力与表心平移惯性的合成效果。

### 2.3 指针几何与质量属性

钟表角从十二点开始、顺时针为正：

\[
\mathbf u(\theta)=(\sin\theta,-\cos\theta,0)
\]

\[
\mathbf t(\theta)=\frac{\partial\mathbf u}{\partial\theta}
=(\cos\theta,\sin\theta,0)
\]

每根指针必须具有：

- 质量 `m>0`；
- 质心 `r_c`；
- 一阶质量矩 `h_0=m r_c`；
- 关于转轴的转动惯量 `I>0`；
- 阻尼和摩擦参数；
- 可选的时间控制、触摸和柔性参数。

对平面刚针至少满足：

\[
I\ge m\lVert\mathbf r_{c,xy}\rVert^2
\]

一般质量分布使用：

\[
\mathbf h(\theta)=R_z(\theta)\mathbf h_0
\]

\[
\tau_{\mathrm{eff}}
=
\left[\frac{\partial\mathbf h(\theta)}{\partial\theta}\right]^T
\mathbf a_{\mathrm{eff},O}^{B}
\]

细杆模型使用：

\[
\tau_{\mathrm{eff}}
=H\mathbf t(\theta)^T\mathbf a_{\mathrm{eff},O}^{B}
\]

其中：

\[
\mathbf h(\theta)=H\mathbf u(\theta)
\]

`H` 是沿所选指针轴向的有符号一阶质量矩，单位为 `kg·m`。`H>0` 表示质心位于显示
指针方向，`H<0` 表示等效配重使一阶矩反向；一般非轴对称质量分布应使用完整 `h(θ)`
向量式，不得强行压缩成标量 `H`。

### 2.4 统一动力学与约化动量

显式形式为：

\[
I\ddot\theta
=
\tau_{\mathrm{effectiveField}}
+\tau_{\mathrm{Euler}}
+\tau_{\mathrm{centrifugal}}
+\tau_{\mathrm{drive}}
+\tau_{\mathrm{time}}
+\tau_{\mathrm{touch}}
+\tau_{\mathrm{external}}
+\tau_{\mathrm{elastic}}
+\tau_{\mathrm{collision}}
+\tau_{\mathrm{damping}}
\]

其中细杆近似：

\[
\tau_{\mathrm{Euler}}=-I\alpha_z
\]

\[
\tau_{\mathrm{centrifugal}}
=
-I(\boldsymbol\Omega\cdot\mathbf u)
  (\boldsymbol\Omega\cdot\mathbf t)
\]

产品首版推荐的权威速度状态是约化动量：

\[
p=I(\dot\theta+\Omega_z)
\]

\[
\dot p
=
\tau_{\mathrm{effectiveField}}
+\tau_{\mathrm{centrifugal}}
+\tau_{\mathrm{relative}}
\]

\[
\dot\theta=\frac pI-\Omega_z
\]

其中：

\[
\tau_{\mathrm{relative}}
=
\tau_{\mathrm{drive}}
+\tau_{\mathrm{time}}
+\tau_{\mathrm{touch}}
+\tau_{\mathrm{external}}
+\tau_{\mathrm{elastic}}
+\tau_{\mathrm{collision}}
+\tau_{\mathrm{damping}}
\]

约化动量模式下不得再次加入 `-Iα_z`，也不得长期并行积分另一个可写的 `θ̇`。

### 2.5 阻尼、势能与功率

被动阻尼模型为：

\[
\tau_{\mathrm{damping}}
=
-c_1\dot\theta
-c_2|\dot\theta|\dot\theta
-\tau_c\tanh(\dot\theta/\omega_\varepsilon)
\]

必须满足：

\[
\boxed{
P_{\mathrm{damping}}
=\tau_{\mathrm{damping}}\dot\theta\le 0
}
\]

固定重力下的势能和相对转动动能可写为：

\[
T_{\mathrm{relative}}=\frac12I\dot\theta^2
\]

\[
U_g=-m\mathbf g^B\cdot\mathbf r_c(\theta)
\]

时间周期势能与柔性势能可写为：

\[
U_{\mathrm{time}}
=K[1-\cos(\theta-\theta_{\mathrm{target}})]
\]

\[
U_{\mathrm{flex}}=\frac12k_\beta\beta^2
\]

一般多自由度模型的瞬时广义功率为：

\[
P_j=\mathbf Q_j^T\dot{\mathbf q}
\]

单根刚针时退化为 `P_j=τ_jθ̇`。

只有在固定基座、恒定保守场、无触摸、无主动控制、无碰撞注能时，才可直接检验机械
能量守恒或衰减。运动基座、时间控制、触摸和外部驱动可以真实地向系统做功。

### 2.6 固定步长基线

基础调度步为：

\[
\Delta t_{\mathrm{base}}=0.01\ \mathrm{s}
\]

每个基础步使用 `1 / 2 / 4` 个固定子步：

\[
\Delta t_{\mathrm{sub}}
=
\frac{\Delta t_{\mathrm{base}}}{N_{\mathrm{sub}}}
\]

约化动量半隐式更新的验收基线为：

\[
p_{k+1}
=
p_k+\sum_{j\in\mathcal C}\Delta p_j
\]

通道集合至少包括：

\[
\mathcal C=
\{
\mathrm{effectiveField},
\mathrm{centrifugal},
\mathrm{drive},
\mathrm{time},
\mathrm{touch},
\mathrm{external},
\mathrm{elastic},
\mathrm{collision},
\mathrm{damping},
\mathrm{event},
\mathrm{safety}
\}
\]

连续力矩通道可使用声明的区间积分或 `τ_jΔt`；事件和安全修正必须作为独立的
`Δp_event/Δp_safety` 记录，不得隐藏在最终状态中。冻结角近似下：

\[
\Delta p_{\mathrm{centrifugal}}
=
-I\mathbf u(\theta)^T
\mathbf M_\Omega
\mathbf t(\theta)
\]

只有当该区间满足冻结角阈值：

\[
\max_s|\theta_s-\theta_k|
\le\theta_{\mathrm{freeze}}
\]

时，才可用整步 `J_eff/M_Ω` 作为充分近似；默认
`θ_freeze=0.01 rad`，也可由场景以更严格误差分析替换。超过阈值时，必须按时间顺序保留
各子步的 `J_eff^(s)`、`M_Ω^(s)` 或原始样本段，不能只用整步总量替代时序。

\[
\dot\theta_{k+1}
=
\frac{p_{k+1}}I-\Omega_z(t_{k+1})
\]

\[
\theta_{k+1}
=
\theta_k+\dot\theta_{k+1}\Delta t
\]

每步必须满足离散动量账本：

\[
r_p
=
(p_{k+1}-p_k)
-\sum_{j\in\mathcal C}\Delta p_j
\approx0
\]

若启用 v2 的线性阻尼隐式分支，其单步基线为：

\[
p_{k+1}
=
\frac{
p_k+\Delta p_{\mathrm{exceptLinearDamping}}
+c_1\Omega_z(t_{k+1})\Delta t
}{
1+c_1\Delta t/I
}
\]

此时必须把隐式线性阻尼的实际动量贡献记为：

\[
\Delta p_{\mathrm{damping,implicit}}
=
p_{k+1}-p_k-\Delta p_{\mathrm{exceptLinearDamping}}
\]

并在 `ΣΔp_j` 中计入一次。禁止的是再叠加一份 `τ_damping,kΔt` 的显式近似。二次阻尼、
平滑库仑摩擦和其他通道包含在 `Δp_exceptLinearDamping` 中，并仍按其声明的离散策略
计账。

子步策略使用最大局部自然/约束频率 `ω_n,max`，它不是指针角速度上限。对单自由度，
先建立位置相关力矩的切线刚度上界：

\[
K_{\mathrm{tan,max}}
\ge
\sup\left|
\frac{\partial\tau_{\mathrm{position}}}{\partial\theta}
\right|
\]

首版保守估计至少包含：

\[
K_{\mathrm{tan,max}}
\ge
|H||a_{\mathrm{eff}}|_{\max}
+K_{\mathrm{time,max}}
+K_{\mathrm{touch,max}}
+K_{\mathrm{elastic,eq}}
+I|\Omega_{xy}|_{\max}^2
+K_{\mathrm{other,max}}
\]

其中最后两项分别覆盖三维离心力矩的切线斜率上界和其他已启用位置相关通道。于是：

\[
\omega_{\mathrm{n,max}}
\approx
\sqrt{\frac{K_{\mathrm{tan,max}}}{I_{\min}}}
\]

多自由度柔性模型必须使用：

\[
\omega_{\mathrm{n,max}}
=
\sqrt{
\lambda_{\max}
\left(M^{-1}K_{\mathrm{tan}}\right)
}
\]

并在其声明的构型范围内取上界。

子步精度策略为：

\[
\omega_{\mathrm{n,max}}\Delta t_{\mathrm{sub}}\le0.1
\quad\text{（精度区）}
\]

\[
0.1<
\omega_{\mathrm{n,max}}\Delta t_{\mathrm{sub}}
\le0.25
\quad\text{（需单独收敛验证的工程区）}
\]

`0.25` 是本项目的保守子步政策，不是对所有非线性系统的充分稳定性证明。稳定性还必须
单独覆盖：

- 速度相关阻尼的最大局部斜率
  `C_tan,max≥sup(abs(∂τ_velocity/∂θ̇))` 及 `C_tan,max Δt_sub/I`；
- 三维离心项；
- 柔性质量矩阵与最高模态；
- 饱和、摩擦、触摸切换和碰撞等非光滑事件；
- 所有主动负阻尼或驱动通道声明的功率上界。

若按 4 子步仍不能满足批准的配置政策，必须拒绝该参数集或改用另行验证的更高频率/
求解器；被测引擎不得在运行中静默降低物理刚度来伪造通过。

## 3. 测试目标与原则

### 3.1 测试目标

| 目标编号 | 目标 |
|---|---|
| `OBJ-01` | 证明坐标、姿态、重力和有效场转换正确 |
| `OBJ-02` | 证明每个力矩项与上游方程逐项一致 |
| `OBJ-03` | 证明质量分布、质心、惯量和材料派生参数作用正确 |
| `OBJ-04` | 证明约化动量和显式方程在适用条件下等价 |
| `OBJ-05` | 证明阻尼被动、势能力矩互为负梯度、能量账本闭合 |
| `OBJ-06` | 证明半隐式积分按预期离散方程执行且随步长收敛 |
| `OBJ-07` | 证明 TIME_REF、触摸和状态机不会绕过动力学写入权威状态 |
| `OBJ-08` | 证明多采样率输入保持冲量、保持时间顺序且只消费一次 |
| `OBJ-09` | 证明极端与异常输入的拒绝、限幅、降级和恢复是确定的 |
| `OBJ-10` | 证明长期和百万级随机运行中无非法状态与未解释发散 |
| `OBJ-11` | 证明引擎结果可重放、可定位、可比较、可扩展 |
| `OBJ-12` | 证明算法成本满足未来 100 Hz MCU 目标的设计预算 |

### 3.2 核心测试原则

#### 原则一：数学状态优先

正确性依据为角度、动量、速度、力矩、能量、约束误差和状态机，不使用截图或肉眼观察
作为通过条件。

#### 原则二：解析判据优先

能得到解析解时必须使用解析解。复杂场景才使用高精度数值参考。

#### 原则三：参考实现独立

参考求解器不得复用被测引擎中的坐标转换、力矩组合或积分函数。否则两套实现可能共享
同一个错误。

#### 原则四：先隔离、后组合

每个公式项先单独启用，再做两两组合，最后做完整场景。完整场景失败不能代替分项测试。

#### 原则五：物理有效输入与故障输入分开

有效随机测试必须保持运动学和物理参数自洽；Fuzz 测试故意破坏数据契约。不得把二者
混成一个“随机稳定性通过率”。

#### 原则六：固定虚拟时间

除性能测试外，测试由虚拟仿真时钟推进，不依赖 PC 墙钟、线程调度或渲染帧率。

#### 原则七：连续事件明确

姿态、角速度和角加速度必须来自同一条自洽运动轨迹。理想阶跃、冲量和模式切换必须被
明确标记为离散事件，并在事件时刻拆步。

#### 原则八：能量判据按系统边界解释

固定被动系统检查能量守恒或衰减；移动基座、触摸和主动控制场景检查能量—功平衡。
不得错误要求所有场景机械能单调下降。

#### 原则九：稳定不等于正确

“不崩溃、没有 NaN”只证明最低鲁棒性。还必须验证方程、收敛、连续性和误差。

#### 原则十：所有失败可复现

任何随机、长期、性能或完整场景失败必须保存种子、参数、输入时间线和首次失败状态。

### 3.3 负对照与测试有效性

测试体系必须能主动识别已知错误模型。至少建立以下变异体或等价负对照：

1. `R_WB` / `R_BW` 使用方向颠倒；
2. 表盘轴交换或一个轴符号翻转；
3. 重力符号翻转；
4. 在 `-f_O` 基础上再次加入 `g^B`；
5. 约化动量模式同时加入 `-Iα_z`；
6. 删除三维离心项；
7. 令离心项对 `Ω→-Ω` 错误变号；
8. 阻尼符号改为正；
9. 只取每个物理步最后一个 IMU 样本；
10. 每个子步重复使用完整基础步冲量；
11. 先用超限速度更新角度，再执行安全限幅；
12. TIME_REF 直接覆盖物理角度；
13. 触摸释放时将动量清零或重复注入释放速度；
14. 用渲染帧率改变物理 `dt`；
15. 动画模式与机械模式同时写同一权威状态。

关键变异必须全部被测试捕获。若测试无法区分正确模型和上述错误模型，测试体系本身不得
通过验收。

## 4. PC 测试架构

### 4.1 总体架构

```text
场景定义 / 参数集 / 随机种子 / 世界真值
                       │
                       ▼
             输入模拟器 Input Simulator
                       │
                       ▼
         被测物理引擎 Physics Simulation Engine
                       │
                       ▼
             状态记录器 State Recorder
                       │
                       ▼
         验证分析器 Verification Analyzer
                       │
                       ▼
       测试报告 / 覆盖矩阵 / 失败回放包 / 性能基线
```

### 4.2 分层输入注入

测试框架必须支持下列互补注入层。每个用例只允许一个动力学权威输入源。

| 注入层 | 注入内容 | 主要用途 |
|---|---|---|
| `INJ-A1` 坐标前端层 | 权威 `q_WB` 与固定 `g^W`；`g^B` 仅作 oracle | 隔离验证姿态到重力的映射 |
| `INJ-A2` 动力学核心层 | 权威 `a_eff`、`Ω`、有序区间量、外部广义输入；`q/g` 仅作元数据或 oracle | 隔离验证力矩、积分器和状态机 |
| `INJ-B1` 融合后生产契约层 | 带时间戳的 `q_WB`、校准比力、角速度、触摸、TIME_REF、数据质量状态 | 验证偏心修正、多速率、区间切分和完整生产数据契约 |
| `INJ-B2` 可选原始适配层 | 原始加速度计/陀螺仪及独立姿态桩 | 验证单位、轴映射与前处理；不据此评定融合算法精度 |

`INJ-A1/A2/B1` 为强制要求。`INJ-B2` 只在原始适配逻辑与物理库同仓时启用。只使用
生产数据链会把姿态、采样和动力学误差混合；只使用数学核心注入又无法发现冲量重复、
乱序和时间对齐错误。

同一用例中出现冗余 `q/g/a_eff/f/J` 时，必须将一个字段声明为权威驱动，其余仅用于
一致性检查；不一致的冗余字段必须按故障策略矩阵处理，绝不能把多份输入叠加成多份力。

### 4.3 世界真值轨迹

真实手表动作的测试输入应先在世界坐标系定义：

\[
\mathbf x_O^W(t),\quad
\mathbf v_O^W(t),\quad
\mathbf A_O^W(t),\quad
q_{WB}(t),\quad
\boldsymbol\Omega^B(t),\quad
\boldsymbol\alpha^B(t)
\]

对于以表盘系表达的本体角速度，应满足：

\[
\dot R_{WB}=R_{WB}[\boldsymbol\Omega^B]_\times
\]

随后再由同一真值生成 `g^B`、理想 IMU 比力、陀螺仪、表心有效场和区间积分。

位于偏心点 `S` 的理想比力必须由同一世界轨迹合成：

\[
\mathbf f_S^B
=
R_{BW}(\mathbf A_O^W-\mathbf g^W)
+\boldsymbol\alpha^B\times\mathbf r_{OS}^B
+\boldsymbol\Omega^B\times
  (\boldsymbol\Omega^B\times\mathbf r_{OS}^B)
\]

该式与第 2.2 节的表心恢复公式必须构成往返测试。

不得随机生成彼此无关的 `q`、`Ω` 和 `α`，再把它们称为一条真实运动轨迹。此类不一致
输入只能作为明确标记的接口故障测试。

### 4.4 输入模拟器

输入模拟器至少包含以下模块：

#### 4.4.1 解析轨迹生成器

必须支持：

- 静止、匀速和匀加速平移；
- 正弦、扫频、带限随机平移；
- 加速度脉冲、梯形速度甩动和 jerk 受限甩动；
- 绕固定轴匀速和匀角加速旋转；
- 单轴倾斜和三轴复合旋转；
- 缓慢旋转、突然停止和反向运动；
- 触摸按下、拖动、保持、饱和、脱手和释放；
- 各指针连续 TIME_REF 与跨十二点目标。

连续轨迹至少应分段 \(C^1\)。需要 `α` 或 IMU 偏心校正时，应优先使用分段 \(C^2\)
轨迹。

#### 4.4.2 坐标与理想传感器合成器

由世界真值独立计算：

- `q_WB`、`R_WB` 和 `R_BW`；
- `gravityVectorBody`；
- `f_S^M`、`f_S^B` 和 `Ω^B`；
- `a_eff,O^B`；
- `J_eff=∫a_eff dt`；
- `M_Ω=∫ΩΩ^Tdt`；
- IMU 偏心位置的切向和向心加速度。

该合成器不得调用被测引擎中的同一函数充当预期结果。

#### 4.4.3 采样与时间线生成器

必须支持：

- IMU 235 Hz、物理基础步 100 Hz；
- 物理 1 / 2 / 4 固定子步；
- IMU、触摸和物理步边界的任意相位；
- FIFO 成批到达但每个样本保留原始时间戳；
- 延迟、抖动、重复、丢失、乱序和时间缺口；
- 基础步追赶、追赶上限和重同步；
- 同一连续场景以至少 16 个采样相位重新生成。

#### 4.4.4 交互生成器

必须能按时间线生成：

- 命中和未命中；
- 进入表心死区；
- 单针捕获和多针独立状态；
- 触摸目标角、角速度和有限抓持；
- 抓持力矩饱和；
- 达到弯曲角或需求力矩阈值后脱手；
- 主动释放、异常中断和重新捕获；
- 无操作定时器、自动回归和立即回归命令。

#### 4.4.5 噪声与故障注入器

理想数学测试默认关闭所有噪声。鲁棒性测试可独立启用：

- 白噪声、固定零偏和缓慢漂移；
- 比例误差、交叉轴和量化；
- 传感器削顶、重复、丢样和 FIFO 溢出；
- 时间戳抖动、倒退和溢出；
- 非单位、零范数、NaN 或 Inf 四元数；
- 非法质量、惯量、阻尼、刚度、限值和 `dt`；
- 触摸事件缺失、重复或非法顺序。

故障输入不要求继续生成有意义的物理解，但必须得到确定的拒绝、钳制、降级或状态重建。

### 4.5 状态记录器

在线硬约束分析必须观察每个物理步或子步，不得只观察渲染帧。短场景、首个失败窗口和
确定性差分场景必须持久化每个子步；百万级和长时测试可使用固定容量环形缓冲、周期检查点
及在线聚合统计，不要求把十亿个子步全部写入文件。检测到失败时必须冻结失败前窗口，并
继续保存规定的失败后窗口。

每条记录至少包含：

- 测试编号、场景版本、随机种子、步骤和子步序号；
- 仿真时间、固定步长和本步消费的输入区间；
- 输入样本编号、原始时间戳和数据质量状态；
- `q_WB`、`g^B`、`a_eff,O^B`、`Ω`、`J_eff`、`M_Ω`；
- 每根指针更新前后的 `θ`、`p`、`θ̇`；
- 每项力矩、总力矩、广义冲量和安全修正；
- 动能、各势能、累计外功和累计耗散；
- 全局及单针状态、控制权、转换原因；
- 饱和、限速、限能、重同步、降级和恢复标志；
- 单次更新耗时、分配次数和工作集信息。

状态记录必须保存原始二进制浮点值。可另行输出可读文本，但格式化文本不得成为确定性
比较的唯一依据。

记录器不得改变输入顺序、仿真步长或状态更新。性能测试需分别测量：

1. 记录关闭；
2. 固定容量内存环形缓冲；
3. 完整异步导出。

核心性能验收以第一种为主，第二种用于评估生产遥测成本，第三种不计入引擎热路径。

### 4.6 验证分析器

#### 4.6.1 每步硬约束分析

每个物理步必须检查：

- 已被 SUT 接受并消费的权威状态全部为有限数；
- 已被接受的四元数、旋转矩阵、参数和时间区间合法；
- 力矩分项之和与总力矩一致；
- `p_{k+1}-p_k` 与全部连续、事件和安全广义冲量之和一致；
- 物理模式及所有交接边界满足 `p≈I(θ̇+Ω_z)`；动画模式按字段 authority 契约检查；
- 阻尼功率不为正；
- 已消费输入区间不重叠且最多消费一次；时间缺口必须被显式标记，不能是未声明缺口；
- 状态机、控制权和力矩通道掩码合法；
- 铰点、刚针长度和柔性几何约束满足容差；
- 安全处理修复的是权威状态，而不只是显示值。

故障注入可以在原始入口产生非法值。硬约束要求非法值在进入权威物理状态前被拒绝、
隔离或按冻结的故障策略转换；不得因为原始入口故意非法而把预期故障测试本身误判失败。

#### 4.6.2 离线分析

离线分析器负责：

- 解析解、高精度参考解和差分模型比较；
- 最大值、RMS、P95、P99、P99.9 和最终状态误差；
- 力矩残差、能量—功平衡残差和长期漂移斜率；
- 步长减半收敛阶；
- 不同采样相位、子步数和渲染频率的等价性；
- 确定性回放和首次分歧定位；
- 覆盖、变异杀伤、性能和内存统计。

### 4.7 失败回放包

任何失败必须生成可独立复现的失败包，至少包含：

- 测试编号、场景版本和失败严重度；
- 根种子、派生种子和缩减后的最小输入；
- 完整参数、初态和输入时间线；
- 引擎版本、配置哈希和数据格式版本；
- CPU、操作系统、编译器、编译选项和浮点模式；
- 第一个失败步及失败前后的状态窗口；
- 理论值、实际值、误差公式和生效容差；
- 当步所有力矩、冲量、能量和状态机分项；
- 若为差分测试，保存两侧首次产生差异的字段。

仅输出“随机失败”“误差过大”或最终截图不满足要求。

## 5. 测试输入模型

### 5.1 输入信号族

每种连续输入至少应从以下信号族选择：

| 信号族 | 用途 |
|---|---|
| 常量 | 静态平衡、恒力矩、匀速旋转 |
| 线性斜坡 | 缓慢倾斜、匀角加速 |
| 平滑阶跃 | 停止、模式变化、边界响应 |
| 正弦 | 频率响应和周期基座运动 |
| 多正弦 | 三轴复合运动 |
| Chirp 扫频 | 共振、相位和稳定边界 |
| 有限脉冲 | 甩动、冲量响应 |
| Jerk 受限 S 曲线 | 真实手持加速与突然停止 |
| 带限随机过程 | 连续复杂用户动作 |
| 录制回放 | 未来实测动作的确定性回归 |

除专门的冲量测试外，不得用数学无限阶跃代替真实传感器可产生的有限带宽运动。

### 5.2 输入合法域

有效输入生成器必须保证：

- `m>0`、`I>0`、阻尼参数非负；
- `I≥m|r_c,xy|²`；
- 柔性质量矩阵对称正定；
- 四元数归一、旋转矩阵为正交右手矩阵；
- 时间戳严格单调、区间不重叠；
- 姿态、角速度和角加速度来自一致运动；
- 状态机事件顺序合法；
- 所有物理量在声明的支持包络内。

非法输入生成器必须显式标记预期行为：

- 拒绝本次配置；
- 丢弃样本并保持有限预测；
- 钳制到合法范围；
- 进入明确降级模式；
- 重建受影响的权威状态。

不得将未定义行为列为可接受结果。

### 5.3 参数分区

每个连续参数必须按自己的合法域分区，不得机械地要求所有参数同时覆盖正、负和零：

- 可正可负的状态或输入：精确零、正负极小值、标称正负值和上下边界；
- 严格正参数：最小批准正值、标称值、50% / 90% 支持上界和上界；
- 非负参数：零、极小正值、标称值和上界；
- 枚举或离散参数：每个合法值及每个非法编码；
- 边界外的最小故障值和可能导致溢出/病态的值只进入 Fuzz 故障域。

特别地，`m>0`、`I>0`、`Δt>0`、`ω_ε>0`；阻尼系数非负；`h0=m r_c`；柔性质量矩阵
必须在批准构型域内保持带裕量的对称正定。零或负质量、惯量、时间步和平滑速度不得混入
有效物理随机域。

每个方向输入至少覆盖：

- 三个坐标轴的正、负方向；
- 表盘平面四个象限；
- 三维八个空间象限；
- 相对指针的径向、切向、法向和一般夹角。

事件相位至少覆盖物理步内：

- `0`；
- `0.25Δt`；
- `0.5Δt`；
- `0.75Δt`；
- 边界前一个可表示时间单位；
- 边界后一个可表示时间单位。

### 5.4 随机参数分布

随机输入不得全部使用独立均匀分布。

- 姿态应使用在 `SO(3)` 上无偏的单位四元数生成方法；
- 跨数量级的质量、惯量、刚度和阻尼应使用对数分布；
- 边界附近使用有偏采样；
- 时间序列使用相关、带限过程而不是每步独立白噪声；
- 脉冲持续时间和事件相位单独分层；
- 多参数应保留物理约束和必要相关性。

建议有效随机用例构成：

| 输入类型 | 占比 |
|---|---:|
| 日常标称输入 | 70% |
| 参数或状态边界附近 | 20% |
| 极端但仍合法 | 10% |

非法与故障输入另建独立 Fuzz 批次，不计入上述有效用例比例和物理正确性通过率。有效
物理随机测试与非法 Fuzz 结果必须分别报告。

### 5.5 故障策略矩阵

所有“拒绝、钳制、降级、替代、重建”等允许策略必须在 `G0` 前冻结为版本化
`Fault Policy Matrix`。每个故障类别必须唯一声明：

- 采取的动作；
- 本物理步是否推进；
- 输入区间是否记为已消费；
- 权威 `θ/p` 是否改变；
- 错误码和数据质量状态；
- 恢复前置条件、恢复事件和恢复窗口；
- 失败是否向调用者传播。

建议首版默认策略：

| 故障类别 | 唯一默认动作 |
|---|---|
| 非法质量、惯量、`dt`、刚度配置 | 拒绝配置，不启动或不替换现有合法配置 |
| 非有限传感器样本 | 拒绝该样本、标记数据缺口，不让非法数进入物理状态 |
| 重复或倒退时间戳 | 丢弃且不重复消费区间，记录计数 |
| 已声明采样缺口 | 不延长最后一份甩动力；按固定步降级策略推进并记录 gap |
| 可归一化但范数偏离的四元数 | 在批准范数窗口内归一化并置修正标志 |
| 零范数或非有限四元数 | 拒绝姿态样本，进入批准的姿态降级路径 |
| 超出 4 子步仍不满足子步政策 | 拒绝该参数集，不静默改变刚度 |
| 合法状态触发速度/能量保护 | 修正权威状态，并把修正记为 `Δp_safety` / 能量事件 |

若项目选择不同策略，必须在测试配置中替换上述默认项，并为每个案例绑定一个确定结果。
运行时不得在多个允许结果之间不确定选择。故障策略矩阵未冻结时，相关测试只能标记
`BLOCKED`，不能标记 `PASS`。

## 6. 参考真值与验证判据

### 6.1 判据优先级

同一场景的验证判据按下列优先级组合使用：

1. 解析解；
2. 代数恒等式和物理不变量；
3. 独立高精度数值参考；
4. 差分模型；
5. 变形关系；
6. 版本化黄金轨迹。

黄金轨迹只能用于回归，不能作为数学正确性的唯一证据。

### 6.2 解析判据

至少建立以下解析基准。

#### 6.2.1 无力矩自由转动

\[
\omega(t)=\omega_0
\]

\[
\theta(t)=\theta_0+\omega_0t
\]

约化动量形式且 `Ω_z` 可变、没有广义冲量时：

\[
p(t)=p_0,\qquad
\dot\theta(t)=\frac{p_0}{I}-\Omega_z(t)
\]

#### 6.2.2 恒定力矩

\[
\omega(t)=\omega_0+\frac{\tau}{I}t
\]

\[
\theta(t)=\theta_0+\omega_0t+\frac{\tau}{2I}t^2
\]

测试必须先验证生产离散递推与半隐式 Euler 离散式完全一致，再验证随步长减小向上述连续
解收敛。

#### 6.2.3 纯线性阻尼

\[
\omega(t)=\omega_0e^{-ct/I}
\]

\[
\theta(t)
=
\theta_0+\frac Ic\omega_0(1-e^{-ct/I})
\]

#### 6.2.4 纯二次阻尼

在速度未跨零时：

\[
\omega(t)
=
\frac{\omega_0}
{1+(c_2/I)|\omega_0|t}
\]

#### 6.2.5 静态有效场平衡

细杆一阶矩 `H>0` 时：

\[
\tau_{\mathrm{eff}}
=H(a_x\cos\theta+a_y\sin\theta)
\]

稳定平衡满足指针质心方向与平面有效场同向：

\[
\mathbf u(\theta_{\mathrm{eq}})
\parallel
\mathbf a_{\mathrm{eff},xy}
\]

等价角度可写为：

\[
\theta_{\mathrm{eq}}
=
\operatorname{atan2}(a_x,-a_y)
\pmod{2\pi}
\]

表盘竖直、重力朝 `+y_B` 时，稳定方向为六点。

#### 6.2.6 有效场冲量

脉冲期间 `θ` 近似不变时：

\[
\Delta p
\approx
H\mathbf t(\theta)^T\mathbf J_{\mathrm{eff}}
+\Delta p_{\mathrm{other}}
\]

若同时发生法向角速度变化：

\[
I\Delta\dot\theta
\approx
H\mathbf t(\theta)^T\mathbf J_{\mathrm{eff}}
-I\Delta\Omega_z
\]

#### 6.2.7 小角线性回归

未饱和 PD 使用：

\[
K_p=I\omega_n^2,\qquad
K_d=2\zeta I\omega_n
\]

应与对应二阶系统的固有频率、阻尼比、超调和收敛时间一致。

#### 6.2.8 势能梯度数值 oracle

验证 `Q=-∂U/∂q` 时，在局部未包裹坐标上使用独立中心差分。`float64` 初始差分尺度建议：

\[
\varepsilon_i
=
\sqrt[3]{\epsilon_{\mathrm{machine}}}
\max(S_{q_i},|q_i|)
\]

对周期角不得把巨大未包裹圈数代入上式；应先在局部包裹相位/重基准坐标上取
`S_q=1 rad`，再把微小扰动映射回逻辑状态。非周期坐标使用带单位的预声明 `S_q`。

还必须使用 `ε_i/2` 重算并确认差分 oracle 自身已进入稳定区。最终比较使用第 6.7 节的
广义力字段级 `atol+rtol+scale`，不得对有量纲力矩直接套固定的 `10⁻⁷`；理论零梯度
使用明确绝对容差。

### 6.3 高精度数值参考

无简单解析解的场景使用独立高精度参考：

- 使用 `float64` 或更高精度；
- 使用独立 RK4、RK5/8 或自适应高阶方法；
- 参考步长不得大于产品子步的 `1/16`；
- 再将参考步长减半，两个参考结果的差必须小于被测容差的 10%；
- 在触摸、饱和、状态切换和冲量等非光滑事件时精确拆步；
- 不得复用产品力矩组合实现；
- 参考求解器本身必须通过解析场景和步长收敛测试。

### 6.4 差分判据

至少建立以下差分对：

1. 四元数旋转与独立矩阵旋转；
2. 显式重力加平移惯性力矩与合成有效场力矩；
3. 平滑 `Ω_z(t)` 下显式 `-Iα_z` 与约化动量模型；
4. 生产 `float32` 路径与 PC `float64` 路径；
5. 生产半隐式 Euler 与独立高精度参考；
6. 高频 IMU 逐段积分与 BaseInterval 预积分；
7. `100 Hz × 4` 子步与等效 `400 Hz` 参考；
8. 表心理想 IMU 与偏心 IMU 经校正后的结果；
9. 一般一阶矩向量形式与细杆 `H t^Ta_eff` 特例；
10. `β≡0` 的受约束二段模型与 `I_eq/H_eq` 等效刚针；高刚度序列在一致初态和同步减小
    步长下与该受约束参考比较。

显式 `α` 与约化动量只在角速度可微且两侧使用一致输入时比较。理想角速度阶跃必须按
冲量和动量连续性验证，不能强行逐点比较两个不同的离散表达。

### 6.6 能量—功判据

能量验证必须先声明“哪些保守项计入势能、哪些通道按外功统计”。同一个通道不得既把
势能变化计入 `E`，又把对应的 `τ·θ̇` 全部计入 `W_in`，否则会双重计数。

定义被验证系统边界内的机械能：

\[
E=T+\sum U
\]

定义主动和基座输入累计做功：

\[
W_{\mathrm{in}}
=
W_{\mathrm{base}}
+W_{\mathrm{time}}
+W_{\mathrm{touch}}
+W_{\mathrm{drive}}
+W_{\mathrm{external}}
+W_{\mathrm{animation}}
+W_{\mathrm{safety}}
+W_{\mathrm{collision}}
\]

定义累计耗散正值：

\[
E_{\mathrm{diss}}
=
-\sum_{j\in\mathcal D}
\int \mathbf Q_j^T\dot{\mathbf q}\,dt
\ge0
\]

其中 `𝒟` 是注册为耗散型的通道集合；单刚针的轴承、二次阻力和平滑库仑摩擦可统一归入
`τ_damping`。

能量平衡残差为：

\[
\boxed{
R_E
=
E(t)-E(0)-W_{\mathrm{in}}+E_{\mathrm{diss}}
}
\]

每个力矩或事件通道必须在测试元数据中注册为以下一种类型：

| 通道类型 | 能量处理 |
|---|---|
| 保守 `conservative` | `E` 包含 `U_j`；`W_j` 只计势能对外部参数的显式时间导数 `∂U_j/∂t` |
| 非保守 `nonconservative` | `E` 不包含该通道势能；`W_j=∫Q_jᵀq̇dt` |
| 耗散 `dissipative` | `E_diss,j=-∫Q_jᵀq̇dt≥0` |
| 离散事件 `discrete event` | 记录事件前后 `ΔE_event`，归入明确事件功/耗散，或在事件处结束并重启能量段 |

同一通道在同一能量段内不得同时注册为多个类型。允许采用两种一致的连续账本：

1. **势能账本**：将重力、有效伪势能、时间势能或弹性势能计入 `E`；对随基座或目标
   显式变化的势能，外部功率按 `∂U/∂t` 统计；
2. **广义功账本**：不把该通道的势能计入 `E`，而按 `Q_jᵀq̇` 对该通道积分做功；单
   自由度时即 `τ_jθ̇`。

例如，对：

\[
U_{\mathrm{eff}}(\theta,t)
=
-\mathbf h(\theta)^T\mathbf a_{\mathrm{eff}}(t)
\]

若它已计入 `E`，基座功率应包含其显式时间项：

\[
P_{\mathrm{base}}
=
\frac{\partial U_{\mathrm{eff}}}{\partial t}
=
-\mathbf h(\theta)^T\dot{\mathbf a}_{\mathrm{eff}}(t)
\]

而不得再把同一 `τ_eff θ̇` 完整计为额外输入功。

若三维离心项未以：

\[
U_{\mathrm{cf}}
=
\frac12I(\boldsymbol\Omega\cdot\mathbf u)^2
\]

纳入势能账本，则 `W_base` 必须包含 `∫τ_cf θ̇dt`。只要 `E` 使用相对动能
`0.5Iθ̇²`，无论求解器采用显式角加速度还是约化动量，`Ω_z` 的变化都必须通过
`∫(-Iα_z)θ̇dt` 或等价的 `Ω_z` 区间/世界系账本计入基座功。约化动量模式只是不得把
这份 Euler 项再加回 `ṗ`。若把 `U_cf` 纳入 `E`，则改为记录它对 `Ω(t)` 的显式时间
导数。

若时间周期势能已计入 `E`，在固定 `K` 时：

\[
\frac{\partial U_{\mathrm{time}}}{\partial t}
=
\tau_K\omega_{\mathrm{target}}
\]

其中 `τ_K=-K sin(θ-θ_target)`；不得再把同一保守刚度通道的 `τ_K θ̇` 计入
`W_time`。若 `K` 随时间变化，还必须加入对应的 `K̇` 参数功率项。

动画直接写状态、安全夹紧、碰撞冲量、释放冲量和角度重基准必须记录离散事件前后的
`ΔE_event`，分别归入 `W_animation/W_safety/W_collision` 等通道；若无法给出物理功解释，
必须在事件处结束当前能量验证段，不能跨事件声称账本闭合。

移动与三维旋转基座的严格参考测试应优先在世界惯性系计算刚体能量和铰点约束功，再与
表盘系账本差分，避免非惯性系漏项。功率积分和事件求积方法必须作为场景实例的一部分
冻结，参考分析器不得与生产账本共享实现。

判定规则：

- 固定基座、无主动输入、无阻尼：能量误差有界、无长期单向漂移；
- 固定基座、被动阻尼：能量包络下降，阻尼功率始终非正；
- 运动基座、触摸或控制：允许机械能增加，但 `R_E` 必须在容差内；
- 半隐式 Euler 的保守能量可在有限包络内振荡，不要求每步严格不变；
- 近零总输入功时使用绝对能量尺度，不得用接近零的相对分母。

### 6.7 统一误差定义

周期角误差：

\[
e_{\theta,\mathrm{periodic}}
=
\left|
\operatorname{atan2}
  (\sin(\theta-\theta_{\mathrm{ref}}),
   \cos(\theta-\theta_{\mathrm{ref}}))
\right|
\]

未包裹轨迹误差：

\[
e_{\theta,\mathrm{unwrap}}
=
|\theta_{\mathrm{unwrap}}-\theta_{\mathrm{ref,unwrap}}|
\]

标量近似判据：

\[
|x-x_{\mathrm{ref}}|
\le
\mathrm{atol}_x
+\mathrm{rtol}_x
\max(|x|,|x_{\mathrm{ref}}|,S_x)
\]

向量使用对应范数。`S_x` 是场景声明的非零物理尺度。

等价地定义统一判定比：

\[
\rho_x
=
\frac{\lVert x-x_{\mathrm{ref}}\rVert}
{\mathrm{atol}_x+
 \mathrm{rtol}_x
 \max(\lVert x\rVert,\lVert x_{\mathrm{ref}}\rVert,S_x)}
\]

通过条件为 `ρ_x≤1`。字段级容差注册表必须为每个量声明单位、`atol`、`rtol`、`S_x`
及适用的浮点路径。严格零值判据仍必须使用非零 `atol`，不得只算相对误差。

归一化均方根误差定义为：

\[
\mathrm{NRMSE}_x
=
\frac{
\sqrt{\frac1N\sum_{k=1}^{N}
\lVert x_k-x_{\mathrm{ref},k}\rVert^2}
}{
\max(
S_{x,\mathrm{RMS}},
\sqrt{\frac1N\sum_{k=1}^{N}
\lVert x_{\mathrm{ref},k}\rVert^2})
}
\]

`S_x,RMS` 必须由场景参数集给出，不得由被测结果事后选择。

力矩尺度建议：

\[
S_\tau
=
\max(
|H||a_{\mathrm{eff}}|,
I|\alpha|,
\tau_{\mathrm{control,max}},
10^{-12}\ \mathrm{N\,m})
\]

能量尺度建议：

\[
S_E
=
\max(
\tfrac12I\omega_{\mathrm{scale}}^2,
|H||a_{\mathrm{scale}}|,
K_{\mathrm{time}},
k_\beta\beta_{\mathrm{scale}}^2,
10^{-12}\ \mathrm J)
\]

尺度只能由当前测试实际启用的参考通道和预先声明的特征量构造。禁用通道、与本案例无关
但上限很大的控制器或安全 cap 不得进入分母并掩盖当前通道的符号/倍率错误。理论零值
场景必须使用按单位定义的字段级 `atol`。

内部累计转数和连续性必须比较未包裹角。只有显示等价和最短目标误差才使用周期角。

### 6.8 精度等级

| 等级 | 用途 | PC `float64` | MCU 等价 `float32` |
|---|---|---:|---:|
| `A0` | 纯代数、矩阵、四元数 | `rtol≤1×10⁻¹⁰` 且 `atol≤rtol·S_x` | `rtol≤3×10⁻⁵` 且 `atol≤rtol·S_x` |
| `A1` | 单步力矩、势能梯度、状态转换 | `rtol≤1×10⁻⁹` 且 `atol≤rtol·S_x` | `rtol≤1×10⁻⁴` 且 `atol≤rtol·S_x` |
| `C1` | 光滑轨迹收敛 | 观测阶数 `order_observed≥0.8` | 同左 |
| `C2` | 精度区轨迹 | 5 个特征周期 NRMSE `≤1%` | 同左 |
| `S1` | 稳定性 | 百万步无非法状态 | 同左 |
| `D1` | 被动耗散 | 阻尼功率非正、无外功时能量包络不增长 | 同左 |

`C2` 同时要求：

- `ω_n,max Δt_sub≤0.1`；
- 振幅误差 `≤2%`；
- 相位误差 `≤2°`；
- 单样本角度最大误差不得超过该场景声明的硬上限。

半隐式 Euler 为一阶全局精度。对 `Δt、Δt/2、Δt/4`：

\[
\mathrm{order}_{\mathrm{observed}}
=
\log_2\left(
\frac{E_{\Delta t}}{E_{\Delta t/2}}
\right)
\]

其中 `E_Δt` 是在共同时间点相对独立参考解的同一误差范数；若使用三网格
Richardson 差分，则相应使用
`norm(x_Δt-x_Δt/2) / norm(x_Δt/2-x_Δt/4)`。

在进入浮点噪声区前必须满足 `order_observed≥0.8`，且连续减小步长不得出现误差持续反增。

### 6.9 标称轨迹默认容差

在标称参数包络、100 Hz 基础步、规定子步策略下，10 秒连续复杂轨迹与独立参考比较：

| 指标 | 默认验收值 |
|---|---:|
| 角度 RMS 误差 | `≤0.01 rad` |
| 角度最大误差 | `≤0.03 rad` |
| 角速度 RMS 误差 | `≤0.05 rad/s` |
| 角速度最大误差 | `≤0.15 rad/s` |
| 无外部冲量的模式切换动量跳变 | 归一化 `≤1×10⁻⁴` |
| 能量—功平衡归一化 RMS | `≤0.5%` |
| 能量—功平衡 P99.9 | `≤2%` |
| 标准平滑场景能量—功单样本硬上限 | `≤5%` |

极端支持边界以有限性、安全策略、稳定性和步长收敛为主，不强行套用标称轨迹误差。
所有容差必须集中版本化，不得为单个失败案例临时放宽。

`0.5%` 等百分比冲量和动量指标只适用于：

\[
|x_{\mathrm{ref}}|
\ge
10(\mathrm{atol}_x+\mathrm{rtol}_xS_x)
\]

的参考值。参考量低于该阈值时，必须使用第 6.7 节的 `atol+rtol+scale` 判据。任何百分比
门槛均不得以接近零的参考值为分母。

## 7. 测试分类

### 7.1 数学正确性测试

目标是证明引擎实现了指定公式，而不是另一个“看起来合理”的公式。

必须覆盖：

- 四元数、旋转矩阵和坐标往返；
- 重力向量三轴分量；
- 比力、表心加速度和有效场关系；
- IMU 安装偏心修正；
- 指针轴向、切向、质心、一阶矩和惯量；
- 重力、平移惯性、欧拉、离心和各相对力矩；
- 势能负梯度与力矩；
- 约化动量和角速度关系；
- 半隐式 Euler 的离散递推；
- 周期角误差与未包裹状态；
- 时间、触摸和柔性模型的单步方程。

每个公式至少应具有：

1. 一个独立代数或解析测试；
2. 一个数值轨迹测试；
3. 一个能发现符号、倍率或重复项错误的负对照。

### 7.2 物理规律测试

必须验证：

- 无力矩时动量连续；
- 固定保守系统能量有界；
- 被动阻尼不做正功；
- 外力消失后状态连续，不被错误清零；
- 倾斜设备产生正确方向的重力力矩；
- 表心加速度产生相反方向的惯性响应；
- 匀速平移不影响相对角动力学；
- 匀速法向旋转不产生细杆离心广义力矩；
- 触摸和主动控制做功可被能量账本解释；
- 各指针仅通过声明的共享基座输入关联，不发生状态串扰。

### 7.3 数值正确性与稳定性测试

必须验证：

- 离散递推顺序；
- `dt、dt/2、dt/4` 的收敛；
- 1 / 2 / 4 子步选择；
- 稳定区、精度区和拒绝区；
- 冲量和 `M_Ω` 区间积分；
- 输入区间在子步边界的切分；
- 长时间未包裹角精度；
- 有限值、安全限幅和权威状态修复；
- 调度延迟不转换成任意大可变 `dt`。

### 7.4 状态机与交互测试

必须覆盖：

- 时间控制、物理自由、触摸约束、回归和降级状态；
- 所有合法转换与禁止转换；
- 触摸优先于时间回归；
- 触摸期间基座状态仍被连续跟踪；
- 释放后 `θ`、`p`、柔性状态和基座状态连续；
- TIME_REF 始终前进但不拥有物理状态写权限；
- 三根指针独立捕获、回归和完成判定；
- 动画、机械和混合模式的唯一写权限。

### 7.5 极端输入测试

至少覆盖：

- 声明支持范围内的最大加速度、角速度、角加速度、刚度、阻尼和初速度；
- 快速三轴旋转和强甩动；
- 突然停止和反向；
- 高频扫频和接近固有频率输入；
- 角度跨越大量圈数；
- `H≈0`、极小惯量和接近柔性质量矩阵退化边界；
- 平面重力趋近零；
- 同一步内多个离散事件；
- 传感器饱和、断流、重复、乱序和恢复。

检查重点为：

- 不出现 NaN、Inf、越界和未定义行为；
- 不发生输入规模无法解释的状态爆炸；
- 不突破已配置的安全限制；
- 保护路径不隐藏错误、不产生角度瞬移；
- 降级和恢复具有确定性。

### 7.6 Property-Based Testing

从合法输入域随机生成初始状态、姿态、运动、参数和交互，逐步验证不变量、变形关系和
收敛性质。硬不变量必须 100% 通过。

### 7.7 结构化 Fuzz 测试

故意生成非法数据契约和二进制边界输入，验证：

- 不崩溃、不越界、不死循环；
- 不无限分配；
- 不把非法数传播到后续有效快照；
- 拒绝、钳制、降级或重建行为符合接口契约；
- 同一故障输入可确定性回放。

Fuzz 通过不表示物理模型正确，Property-Based 通过也不表示非法输入处理安全。

### 7.8 差分、变形与回放测试

复杂场景同时使用：

- 生产 `float32` 与独立 `float64`；
- 半隐式 Euler 与高阶参考；
- 分项公式与合并公式；
- 传感器逐段积分与区间预积分；
- 原场景与变形场景；
- 在线输入与录制回放。

### 7.9 长时间稳定性测试

长时间测试必须区分：

- 模拟时间长：快速推进数百万步，检查数值累计；
- PC 墙钟长：持续实际运行，检查内存、资源和偶发状态；
- 周期数长：对摆和回归模型检查能量包络与相位；
- 圈数长：检查未包裹角和包裹函数。

### 7.10 性能与资源测试

性能测试与正确性测试使用相同生产安全检查，但关闭文件导出和文本格式化。必须测量更新
时间分布、复杂度、工作集、栈、动态分配和长期增长。

## 10. Property-Based、随机压力与 Fuzz 要求

### 10.1 有效随机生成

随机生成器至少覆盖：

- 初始 `θ、p、θ̇` 和柔性状态；
- 均匀分布的 `SO(3)` 姿态；
- 连续平移加速度、三轴角速度和角加速度；
- 有效场脉冲、斜坡、正弦、扫频和带限噪声；
- 触摸捕获、拖动、饱和、释放和中断；
- TIME_REF 变化与状态机转换；
- 每根针不同质量、一阶矩、惯量、阻尼和控制参数；
- 1 / 2 / 4 子步和合法时间戳组合；
- 标称、边界和极端合法参数。

有效随机初态只能在 `p` 与 `θ̇` 中选择一个权威随机量，另一个必须由
`p=I(θ̇+Ω_z)` 派生。将 `p` 和 `θ̇` 相互独立随机只属于双权威状态故障域。

### 10.2 每步硬不变量

百万级有效随机测试的每个物理步至少检查：

\[
\operatorname{isfinite}
(\theta,p,\dot\theta,\tau_j,E_j)=\mathrm{true}
\]

\[
m>0,\quad I>0,\quad
I\ge m|\mathbf r_{c,xy}|^2
\]

\[
\lVert q\rVert\approx1,\quad
R^TR\approx I,\quad
\det R\approx+1
\]

\[
\lVert\mathbf g^B\rVert\approx g_0
\]

\[
p\approx I(\dot\theta+\Omega_z)
\quad
\text{（物理模式与模式交接边界）}
\]

\[
\tau_{\mathrm{damping}}\dot\theta\le0
\]

\[
\sum_j\tau_j\approx\tau_{\mathrm{total}}
\]

\[
\tau_g+\tau_{\mathrm{translation}}
\approx\tau_{\mathrm{effectiveField}}
\]

并检查：

- `p_{k+1}-p_k≈Σ_jΔp_j`，其中包含事件和安全通道；
- `τ_eff(a)≈-τ_eff(-a)`；
- `τ_cf(Ω)≈τ_cf(-Ω)`；
- 每个输入时间区间和冲量最多消费一次；
- 所有启用力矩与状态机掩码一致；
- 刚针长度、铰点和柔性约束满足容差；
- TIME_REF 不直接改写物理角；
- 模式切换满足规定连续性；
- 指针间不存在未声明状态耦合；
- 渲染频率、对象更新顺序不改变物理结果。

这些硬不变量作用于被 SUT 接受和消费后的数据。故障注入入口允许非法，但非法输入不得
进入权威物理状态；声明的数据缺口可以存在，未声明缺口、区间重叠和重复消费不得存在。

持续外部驱动可以让未包裹角持续增加，这本身不是发散。真正的硬失败是：

- NaN 或 Inf；
- 超出理论增长阶；
- 无输入的持续能量爆炸；
- 安全限制已生效但权威状态仍非法；
- 状态机死锁或不可恢复；
- 输入被重复或遗漏消费。

### 10.3 随机规模

| 执行层级 | 最低用例与步数 |
|---|---:|
| 提交前快速门 | `≥10,000` 个单步属性；`≥200` 条 1～10 秒轨迹 |
| 持续集成门 | `≥100,000` 个短用例；累计 `≥10,000,000` 物理步 |
| 每夜完整门 | `≥1,000,000` 个用例；累计 `≥100,000,000` 物理步 |
| 每周扩展压力 | 累计 `≥1,000,000,000` 物理子步 |
| 单条长轨迹 | 至少 24 小时模拟时间，即 100 Hz 下 `8,640,000` 基础步 |

关键属性通过率必须为 `100%`。一个硬失败即阻断对应测试门。

当一百万个独立用例零失败时，按零事件经验上界，只能说明在 95% 置信水平下未知失败
概率约小于 `3×10⁻⁶`，不得宣传为“绝对无缺陷”。

### 10.4 种子、回放与反例缩减

每个随机用例必须保存：

- 根种子与派生种子；
- 参数集；
- 输入轨迹；
- 首次失败步；
- 失败前后的最小状态窗口；
- 引擎、编译和浮点环境。

反例缩减必须尝试：

- 缩短轨迹；
- 删除无关事件；
- 降低输入幅值；
- 从三轴缩减到单轴；
- 从三针缩减到单针；
- 将参数缩回标称；
- 将失败时刻提前；
- 保留四元数、时间戳和质量属性的合法性。

### 10.5 结构化 Fuzz 输入

至少包括：

- NaN、Inf、负零、非正规数和极端有限值；
- 非单位或零四元数；
- 零/负质量、惯量、长度、时间步；
- 负阻尼、超大刚度和病态质量矩阵；
- 重复、倒退、溢出和不连续时间戳；
- 空、重叠、超长输入区间；
- IMU 削顶、FIFO 溢出和冲突数据质量状态；
- 同一离散事件重复到达；
- 触摸开始后永久缺少 release；
- 恢复期间再次进入新模式；
- 配置版本、单位或坐标标签不匹配。

Fuzz 验收要求：

- 零崩溃；
- 零未定义行为；
- 零越界和死循环；
- 零无界内存增长；
- 非法数不传播到下一份有效快照；
- 每次拒绝或恢复均有明确状态；
- 同一输入得到相同结果。

### 10.6 随机覆盖报告

报告不能只给出用例数。至少报告：

- 姿态和方向桶命中数；
- 输入幅值和参数区间命中数；
- 径向、切向、法向和一般夹角命中数；
- 各状态、状态转换和拒绝转换命中数；
- 每个力矩通道正、负、零和饱和命中数；
- 事件相位桶命中数；
- 1 / 2 / 4 子步命中数；
- 标称、边界、极端和故障域命中数；
- 首次失败和缩减成功率。

每个强制覆盖桶在夜间测试中至少命中 `1,000` 个单步样本或 `100` 条有效轨迹。

### 11.3 能量长期验收

能量验收按无量纲步长分区：

| 条件 | 验收要求 |
|---|---|
| `ω_n,maxΔt_sub≤0.05` 的标准保守基准 | 100 个自然周期能量包络峰峰偏差 `≤5%`，无正向线性漂移 |
| `0.05<ω_n,maxΔt_sub≤0.1` | 100 个自然周期能量包络峰峰偏差 `≤15%`；在渐近区步长减半后对应误差比 `E_Δt/E_Δt/2≥1.5` |
| `0.1<ω_n,maxΔt_sub≤0.25` | 只要求有界和收敛趋势，必须按具体场景另定精度门槛 |
| 被动耗散 | 多周期能量包络不增长，累计阻尼耗散非负 |
| 有外部做功 | 能量—功残差满足第 6.9 节，不要求机械能单调 |

“无正向线性漂移”应通过多个完整周期的峰值序列拟合判断，不能只比较任意两个时间步。

### 11.4 资源长期验收

预热后：

- 引擎核心未释放对象数不得增长；
- 每步动态分配必须为零；
- 核心引擎净内存增长必须为 `0 B`；
- 若以整个测试进程 RSS 观测，24 小时首尾增长应 `≤1 MiB`，且预热后线性回归斜率
  的 95% 置信上界应 `≤64 KiB/h`；
- 固定容量记录器满后只允许覆盖旧记录并增加计数，不得扩容；
- 不得泄漏文件句柄、线程、锁或同步对象；
- 单步执行时间分布不得随运行时长持续恶化。

## 12. 性能测试要求

### 12.1 性能结论分层

| 层级 | 环境 | 可以证明 | 不可以证明 |
|---|---|---|---|
| PC 性能 | 指定 x86-64 基准机 | 算法成本、复杂度、版本回退、批量测试能力 | ESP32-S3 的真实最坏时延 |
| MCU 目标预审 | PC 上的接口、操作计数、工作集分析 | 算法具备移植预算 | 真实调度竞争下按时完成 |
| 未来 MCU 实测 | ESP32-S3 Release 构建 | 100 Hz 截止期与资源占用 | 不在本阶段执行 |

渲染目标最低为 30 FPS，但渲染不属于本说明书的被测对象。其约束含义仅为：物理任务
不得占满计算资源，且物理快照发布不得被渲染阻塞。

### 12.2 标准性能负载

| 负载 | 内容 | 用途 |
|---|---|---|
| `LOAD-BASE` | 3 根刚针、1 子步、重力与线性阻尼 | 最小产品基线 |
| `LOAD-FULL` | 3 根刚针、4 子步、所有刚体力矩、时间目标和触摸状态机启用 | 强制验收负载 |
| `LOAD-EXT` | 3 根柔性针或当前最高复杂度扩展、4 子步 | 扩展能力评估 |
| `LOAD-SCALE` | 1 / 3 / 8 / 16 / 32 个相互独立对象，1 / 2 / 4 子步 | 复杂度与扩展性 |

`LOAD-FULL` 必须保留生产安全检查、状态机和限幅。不得为得到漂亮的性能数字而删除正式
路径。

### 12.3 PC 测量条件

每份报告必须记录：

- CPU 型号、微码、核心与频率策略；
- 操作系统和内核；
- 编译器、版本、优化等级和浮点选项；
- 引擎版本、配置哈希和数据集版本；
- 浮点类型、单线程或绑核策略；
- 是否关闭睿频、是否存在后台竞争；
- 记录器模式。

每种负载应：

1. 预热不少于 `100,000` 个基础步；
2. 正式测量不少于 `10,000,000` 个基础步；
3. 至少运行 5 轮；
4. 报告平均、标准差、P50、P95、P99、P99.9 和最大值；
5. 同时报告每基础步和每物理子步耗时；
6. 使用同一输入轨迹做跨版本比较；
7. 保留全部原始样本，不得在测试后人工删除离群点；
8. 另做预先声明的隔离基准轮：固定核心、预触页、固定频率策略并记录 page fault、
   非自愿上下文切换和系统中断计数；
9. 隔离轮若发生预定义污染事件，应整轮作废并重跑，不得只删除受影响的单个样本。

### 12.4 PC 初始验收门槛

在批准的基准机、Release 优化、`LOAD-FULL` 负载、关闭外部导出的条件下：

| 指标 | 初始门槛 |
|---|---:|
| 平均基础步耗时 | `≤0.10 ms` |
| P99 基础步耗时 | `≤0.20 ms` |
| P99.9 基础步耗时 | `≤0.30 ms` |
| 隔离基准轮最大值 | `≤1.00 ms` |
| 批处理相对实时速度 | `≥100×` |
| 相对批准基线的 P99 回退 | `≤10%` |

绝对时延只对批准的基准机有效。基准机更换时必须重新建立绝对基线，但 `≥100×` 实时、
复杂度要求和相对回退门槛仍有效。非隔离原始最大值必须报告，但不作为 PC 通用硬截止期；
只有隔离基准轮最大值使用上表门槛。

### 12.5 PC 内存与分配

`LOAD-FULL` 的初始 PC 资源门槛为：

| 指标 | 门槛 |
|---|---:|
| 引擎自有持久状态、参数和固定工作区 | `≤32 KiB` |
| 单次更新临时工作区 | `≤16 KiB` |
| 单次更新堆分配 | `0 B / 0 次` |
| 10,000,000 步后的引擎净增长 | `0 B` |
| 相对批准基线的持久工作集回退 | `≤10%` |

PC 的 64 位指针和对齐会使对象布局不同于 MCU，因此该门槛不替代第 12.7 节的 MCU
`16 KiB` 目标。参考求解器、场景生成器、失败保存和长日志内存不计入引擎核心，但必须
在测试报告中单列。

### 12.6 复杂度验收

对相互独立、没有碰撞的对象：

\[
T
\propto
N_{\mathrm{object}}N_{\mathrm{substep}}
\]

验收要求：

- 对象数翻倍时，耗时增长不得超过 `2.2×`；
- 子步数 1 → 2 → 4 时，扣除固定开销后的线性拟合 `R²≥0.99`，各点相对拟合值偏差
  `≤15%`；
- 持久状态和工作区随对象数线性增长；
- 不得因对象相互独立而出现隐含 `O(N²)`；
- 若未来加入碰撞，碰撞检测和求解成本必须单独统计。

### 12.7 未来 ESP32-S3 实时预算

目标基础频率：

\[
f_{\mathrm{physics}}=100\ \mathrm{Hz},
\qquad
\Delta t_{\mathrm{base}}=10\ \mathrm{ms}
\]

一个基础步包含全部三针和全部 1 / 2 / 4 子步。

未来实机的验收目标为：

| 指标 | 目标 |
|---|---:|
| 平均物理 CPU 预算 | `≤20%` 单核等效时间 |
| P99 基础步执行时间 | `≤1.0 ms` |
| P99.9 基础步执行时间 | `≤2.0 ms` |
| 观测最坏执行时间 | `≤5.0 ms` |
| 绝对截止期 | `<10.0 ms` |
| 正常模式 deadline miss | `0` |
| 运行中动态内存分配 | `0` |
| 引擎核心持久状态、参数和工作区 | `≤16 KiB` |
| 物理任务峰值栈 | `≤8 KiB` |

`1 ms` 是设计目标，`2 ms` 是尾延迟目标，`5 ms` 是观测安全上限，`10 ms` 是不可逾越
的基础步截止期。即使平均耗时很低，也不能接受偶发超过 10 ms。

MCU 最终验收必须使用：

- 最终 ESP32-S3 硬件；
- Release 优化和最终 `float32` 路径；
- 三根指针、4 子步；
- 所有默认启用物理项和安全检查；
- 最坏但合法参数组合；
- 实际 IMU、触摸、渲染和日志任务竞争；
- 不少于 `10,000,000` 个连续基础步。

PC 阶段对 MCU 的“静态预审”只可判定：热路径零动态分配、核心工作集、固定循环上界、
对象/子步复杂度和最坏配置路径已知。它不能判定 ESP32-S3 的 P99 或 deadline；这些指标
只能由上述未来实机测试通过。

### 12.8 调度异常预算

测试必须确认，调度延迟发生时：

- 物理仍使用固定 `dt`；
- 补算基础步有明确上限；
- 同一输入冲量不重复；
- 丢弃、合并或重同步均产生诊断；
- 不用一个巨大 `dt` 追赶；
- 降级不产生 NaN、Inf 或无来源角度跳变；
- 30 FPS 或更低渲染不改变物理轨迹。

## 13. 测试覆盖率要求

### 13.1 需求与模型追踪

必须维护双向追踪矩阵：

```text
上游设计需求
    ↕
物理公式 / 状态约束
    ↕
输入分区 / 测试场景
    ↕
参考判据 / 容差
    ↕
执行结果 / 失败证据
```

任何上游公式没有测试，或任何测试无法追溯到要求与判据，都视为覆盖缺口。

### 13.2 模型覆盖

| 覆盖对象 | 验收要求 |
|---|---:|
| 上游动力学公式 | 100% 至少一个解析/代数测试和一个数值测试 |
| 每个独立力矩项 | 100% 单独启用、单独禁用 |
| 势能与力矩负梯度关系 | 100% |
| 坐标方向、轴符号和旋转约定 | 100% |
| 状态变量的零、正、负、边界 | 100% |
| 合法参数边界 | 100% |
| 非法参数拒绝路径 | 100% |
| 1 / 2 / 4 子步 | 100% |
| `float64` / `float32` 路径 | 100% 核心矩阵 |
| 各模块二元组合 | 100% pairwise |
| 全力矩组合 | 至少一个端到端场景 |

独立力矩项至少包括：

- 重力与平移惯性合成有效场；
- 显式欧拉项或约化动量的等价作用；
- 三维离心项；
- 线性、二次和库仑阻尼；
- 时间控制；
- 触摸约束；
- 外部作用力/广义力矩；
- 驱动、弹性、碰撞和安全限制；
- 柔性模式下的内部弹簧和阻尼。

功能清单中明确“未实现且编译期不存在”的可选通道可标记 `N/A`，并从实现专项覆盖分母
排除；但关闭通道必须仍有零输出测试。通道一旦编入或可配置启用，就不得以 `N/A` 逃避
专项覆盖。

### 13.3 状态与转换覆盖

`G0` 必须冻结版本化 `State Transition Matrix`，每行至少包含：

- 起始状态、事件、守卫条件和目标状态；
- 合法/拒绝结论与错误码；
- 权威状态写入者；
- 各力矩通道启用掩码；
- `θ/p/β` 连续性或声明的事件冲量；
- 数据质量状态和恢复条件。

必须覆盖：

- 每个全局和单针状态；
- 每个合法状态转换；
- 每个禁止或冲突转换；
- 正常、饱和、超时、中断、降级和恢复原因；
- 转换发生在基础步边界、子步内部和多个事件同到时；
- 三针处于相同和不同状态的组合；
- 状态切换前后每个力矩通道掩码。

所有状态转换和安全分支要求 100% 覆盖。

### 13.4 场景覆盖

必须覆盖：

- 静止、缓慢运动、普通手持、突然旋转、甩动、停止和反向；
- 三轴正负方向、平面四象限和三维一般方向；
- 零重力投影、最大重力投影和中间投影；
- 角度跨 `-π/π`、`0/2π` 和大量圈数；
- 单针、三针和不同材料/质量参数；
- 正常回归、回归中触摸、触摸中基座运动；
- 传感器正常、饱和、缺样、乱序和恢复；
- 相位、采样率和子步组合；
- 保守、耗散和受迫能量系统。

### 13.5 未来代码覆盖

本文档不开发测试代码，但后续实现应满足：

| 指标 | 门槛 |
|---|---:|
| 核心数学模块行覆盖率 | `≥95%` |
| 核心数学模块分支覆盖率 | `≥90%` |
| 状态转换与安全分支 | `100%` |
| 关键数据契约拒绝路径 | `100%` |
| 关键方程变异捕获 | `100%` |
| 扩展变异集合杀伤率 | `≥95%` |

代码覆盖率只证明代码被执行，不证明方程正确，不能替代模型、场景和不变量覆盖。

### 13.6 覆盖完成定义

一个需求只有在以下条件全部满足时才算“已覆盖”：

1. 有明确输入域；
2. 有独立参考判据；
3. 有版本化容差；
4. 有正常、边界和反向/负对照；
5. 有至少一次自动化执行结果；
6. 失败时可以生成回放包；
7. 测试确实能杀死对应关键错误变异。

## 14. 测试执行层级与回归门

### 14.1 执行层级

在进入任何“通过”判定前，`G0` 必须冻结支持包络、参数集、场景持续时间、初态、通道
启用表、字段级容差、故障策略和状态转换表。未冻结的“最大合法”“最终收敛”或“按配置”
场景只能为 `BLOCKED`，不得以默认猜测参数执行后标记 `PASS`。

| 测试门 | 内容 | 建议频率 | 通过条件 |
|---|---|---|---|
| `G0` 文档与配置门 | 单位、参数、追踪矩阵、容差版本 | 每次变更 | 无缺失、无冲突 |
| `G1` 快速数学门 | L0～L3 解析、代数、单步和少量属性 | 每次提交 | 全部通过 |
| `G2` 完整 CI 门 | 状态机、多速率、端到端、10 万随机 | 每次合并 | 硬失败为零 |
| `G3` 夜间门 | 100 万随机、复杂轨迹、Fuzz、性能 | 每夜 | 全部硬门槛通过 |
| `G4` 长时门 | 24 小时模拟、7 天加速、长期资源 | 每周 | 无发散、泄漏和趋势退化 |
| `G5` 发布门 | 全矩阵、新种子、变异、跨环境、性能基线 | 每个候选版本 | 第 15 章全部满足 |

### 14.2 确定性要求

同一可执行文件、CPU 架构、编译选项、参数、输入和固定步调度下：

- 每步权威物理状态、派生物理量、虚拟时间状态和确定性数据质量状态必须位级一致；
- 状态转换步骤必须一致；
- 由相同虚拟输入决定的保护、降级和饱和标志必须一致；
- 最终状态哈希必须一致。

墙钟更新时间、CPU 周期、工作集、操作系统调度、page fault、真实 deadline miss 等性能
遥测不得进入确定性状态哈希。此类遥测由性能测试单独比较统计分布。

跨编译器、跨 CPU 或 `float64/float32` 比较只要求满足版本化数值容差，不要求位级一致。

### 14.3 首次分歧定位

长轨迹应周期保存检查点。差分失败时，系统必须能定位：

1. 首个输入差异；
2. 首个坐标或有效场差异；
3. 首个分项力矩差异；
4. 首个动量差异；
5. 首个角度差异；
6. 首个状态机差异。

只比较最终角度不满足要求，因为中间误差可能相互抵消。

### 14.4 基线升级

黄金轨迹、性能基线、参数包络或容差变更时必须：

- 说明上游物理模型是否变化；
- 给出旧、新结果的数学差异；
- 重新执行关键变异测试；
- 不得用“更新黄金文件”掩盖未知回归；
- 经审查后版本化保存。

### 14.5 编译器与浮点可移植性矩阵

发布门至少使用两套独立 C/C++ 编译器工具链，并覆盖：

| 构建 | 浮点模式 | 用途 |
|---|---|---|
| `REF64-STRICT` | IEEE-754 binary64、round-to-nearest、禁止 fast-math | 高精度验证构建 |
| `PROD32-STRICT` | IEEE-754 binary32、禁止不受控重关联 | MCU 等价正确性基线 |
| `PROD32-FMA` | 分别允许/禁止 FMA | 检查融合乘加造成的容差差异 |
| `PROD32-FTZ` | 按未来目标分别启用/禁用 FTZ/DAZ | 检查非正规数处理与零速摩擦 |
| `PROD32-FAST` | 仅当产品计划启用 fast-math 时 | 必须单独完成全部有限值和物理门禁 |

工具链可从 GCC、Clang、MSVC 或目标交叉编译器中选择，但版本、标准库、FMA、
FTZ/DAZ、异常处理和重关联选项必须记录。严格构建是强制基线；fast-math 未计划使用时
可标记 `N/A`，不得让 fast-math 结果反向放宽严格构建容差。

同一构建要求位级回放；跨工具链和浮点模式按第 6.7 节比较。若算法依赖超出上述假设的
浮点行为，必须在数据契约中显式声明并增加专项测试。

## 15. 总体验收标准

### 15.1 强制通过项

物理引擎测试验证只有在以下条件全部满足时方可通过：

1. 所有解析和代数测试通过；
2. 所有坐标、力矩、动量和状态硬约束通过；
3. 所有公式完成双向追踪并具有独立判据；
4. 重力重复、旋转方向和冲量重复哨兵全部通过；
5. 标称轨迹角度、角速度和能量—功误差满足第 6 章；
6. `dt、dt/2、dt/4` 在适用的光滑问题中显示预期收敛；
7. 固定被动系统无持续非物理能量增长；
8. 全部合法输入下阻尼不做正功；
9. 全部测试中 NaN、Inf、越界、未定义行为和死循环为零；
10. 模式切换满足规定的角度、动量和柔性状态连续性；
11. 每份输入区间与冲量最多消费一次；
12. TIME_REF 不直接覆盖机械模式的权威角度；
13. 触摸不暂停未触摸指针，不丢失基座连续状态；
14. 渲染频率和记录器不会改变物理轨迹；
15. 同一运行环境确定性回放位级一致；
16. 每夜百万级有效随机测试硬不变量零失败；
17. 结构化 Fuzz 零崩溃、零未定义行为、零非法数传播；
18. 24 小时等效模拟和规定长时测试无泄漏、状态损坏或趋势退化；
19. PC 性能、复杂度和内存要求通过；
20. 未来 MCU 的内存、分配、循环上界和复杂度静态预审通过，且未用 PC 时延冒充实机
    deadline 结论；
21. 所有关键方程变异均被测试捕获；
22. 任何失败均可由保存的回放包稳定复现。

### 15.2 随机测试通过率

- 硬不变量：必须 `100%` 通过；
- 确定性解析场景：必须 `100%` 通过；
- 非法输入安全性：零崩溃、零未定义行为；
- 统计软误差：允许按 P99.9 管理，但必须同时存在不可越过的单样本硬上限；
- 不得用高总体通过率掩盖单个严重物理反例。

### 15.3 缺陷严重度

| 等级 | 定义 | 示例 | 发布处理 |
|---|---|---|---|
| `P0` | 安全或数学基础失效 | NaN、崩溃、内存破坏、重力重复、冲量重复 | 必须修复 |
| `P1` | 核心物理或状态连续性错误 | 符号错误、不收敛、TIME_REF 覆盖角度、释放清零动量 | 必须修复 |
| `P2` | 标称精度、性能或边界行为未达标 | 相位误差超限、P99 回退、恢复超出容差 | 修复或经正式评审 |
| `P3` | 诊断、报告或非关键覆盖缺陷 | 缺少次要统计字段 | 可计划修复，但不得影响可复现性 |

P0/P1 不允许豁免发布。任何 P2 豁免必须记录数学影响、适用范围、临时保护和截止修复版本。

### 15.4 明确禁止的验收方式

以下方式不得作为通过依据：

- “看起来差不多”；
- 仅播放动画录像或比较截图；
- 只比较最终角度；
- 只检查程序没有崩溃；
- 只检查代码覆盖率；
- 只与同源的第二套实现比较；
- 用调整参数掩盖符号或倍率错误；
- 在失败后直接放宽该个案容差；
- 用 PC 平均耗时宣称 MCU 截止期已通过；
- 删除异常种子或统计离群点而没有原因分析。

## 16. 未来扩展测试体系

### 16.1 扩展模型契约

每个新增物理模型必须声明：

- 权威状态量、单位和坐标系；
- 参数、派生参数和合法范围；
- 输入、时间戳和区间语义；
- 输出观测量；
- 自由度和几何约束；
- 力、力矩、冲量和能量通道；
- 主动与被动功率端口；
- 每步硬不变量；
- 至少一个解析或高精度参考场景；
- 有效随机生成域与非法故障域；
- 序列化、版本和确定性回放格式；
- 预期时间复杂度、空间复杂度和实时预算。

新增模型不得直接覆盖最终角度或位置来伪装物理响应。所有状态变化必须通过声明的动力学、
约束、冲量或明确标记的非物理动画通道产生。

### 16.2 可复用流水线

```text
模型声明 / 参数域 / 世界轨迹 / 随机种子
                    ↓
              输入模拟器
                    ↓
            固定步长物理模型
                    ↓
              标准状态快照
                    ↓
  不变量 / 解析解 / 参考解 / 统计 / 性能分析
                    ↓
          失败缩减与确定性回放
```

新增玩法只增加自己的状态定义、输入生成器、参考模型和不变量，不应复制记录器、回放器、
性能框架和通用分析器。

### 16.3 扩展专项要求

| 扩展模型 | 新增状态或输入 | 可复用验证 | 必须新增的专项不变量 |
|---|---|---|---|
| 发条系统 | 发条角、储能、棘轮状态 | 固定步、能量、状态机、随机测试 | `E_s=½kφ²`；储能非负；释放做功不超过储能；棘轮单向 |
| 上发条倒计时 | 剩余储能、目标时长、耗散率 | 连续时间、回放、长期测试 | 时间映射单调；暂停恢复连续；步长减半时计时误差收敛 |
| 三维陀螺 | 转子姿态、角动量、惯量张量 | 坐标、差分、长期和性能 | 无外力矩时角动量守恒；四元数归一；进动方向与频率正确 |
| 指尖陀螺 | 高速转速、轴承摩擦、接触冲量 | 阻尼、极端输入、长期测试 | 无阻尼时能量有界；转速按模型衰减；冲量连续 |
| 摇号系统 | 多刚体、碰撞、容器约束、随机源 | Property、回放、性能 | 非穿透；碰撞冲量；动量与恢复系数；结果分布另做统计 |
| AI 随机交互 | 带种子、带时间戳的外部动作 | 场景生成、回放、覆盖 | AI 只产生输入，不写物理状态；同种子输入序列可重放 |

### 16.4 摇号和随机体验的双重验收

未来摇号系统必须分开验证：

1. 物理轨迹是否满足动力学、碰撞和约束；
2. 输出结果是否满足声明的概率分布。

物理正确不能证明统计公平，统计看似均匀也不能证明物理正确。概率分布可使用卡方、
Kolmogorov–Smirnov 或适合离散/连续结果的检验，但这些统计检验不得替代动力学不变量。

### 16.5 AI 输入边界

AI 只能作为带时间戳的输入序列生成器：

- AI 不得成为物理真值或验收判据；
- AI 不得直接改写角度、动量或能量；
- AI 输入必须经过与人工交互相同的数据契约和限值；
- 失败必须能用保存的输入序列重放，不依赖再次调用 AI；
- 物理安全、不变量和确定性门槛不因输入来源为 AI 而降低。

### 16.6 向后兼容

新增模型后：

- 旧输入轨迹仍应可回放；
- 未启用新功能时，旧模型结果不得无说明变化；
- 状态记录格式必须带版本、单位和坐标声明；
- 新增力矩项必须能单独开关；
- 性能报告分别给出基础模型与扩展模型；
- 新模型不得削弱现有硬不变量和安全门槛。

## 文档结论

本说明书把实时物理仿真表盘的验证目标分为三层：

1. **公式正确**：证明实现的坐标、力矩、动量和约束与上游数学模型一致；
2. **数值正确**：证明固定步求解在声明范围内稳定、连续并向参考解收敛；
3. **系统正确**：证明多速率输入、状态交接、随机压力、长期运行和资源预算均满足要求。

只有三层同时通过，才能认为物理引擎具备进入后续 C/C++ 实现迭代和未来 MCU 验证阶段
的测试基础。“视觉上像真实机械”可以作为体验评价，但不能替代本文档规定的数学与工程
验收。
